# QQ 音乐搜索诊断

适用于 LX-M 2.3.0、2.4.0 和洛雪 LX 2.12.2，无需修改或重新安装软件。

1. 打开软件的开发者工具，进入 Console（控制台）。
2. 用文本编辑器打开同目录的 `qq-search-diagnostics.js`，复制全部内容，粘贴到控制台执行。
3. 搜索反馈中使用的词，例如 `Talullah Jamiroquai`。如果失败，稍等几秒后再点重试；最好同时记录到一次失败和一次成功。
4. 在控制台执行下面的命令，将结果复制出来并保存为 `qq-search.json`：

```js
copy(window.__lxQqSearchCapture.export())
```

5. 执行下面的命令停止诊断：

```js
window.__lxQqSearchCapture.stop()
```

脚本只在当前窗口临时观察现有 QQ 请求，不发送额外请求，不修改请求参数或返回内容。最多观察 40 次请求，10 分钟后自动停止；重启软件也会移除它。日志保留版本、HTTP 状态、QQ 业务码、歌曲数量和耗时，不记录关键词、Cookie、签名、账号信息或完整响应。

反馈时附上软件版本、搜索词，以及是否使用软件代理、系统代理或 VPN。`HTTP 200` 只表示服务器返回了响应；还要查看 `code` 和 `reqCode`。例如 `code: 0, reqCode: 2001` 表示 QQ 搜索请求未成功，不能当作搜索结果为空。仅凭该业务码无法确定具体平台限制，需要对比同一机器上的失败和成功记录。

## 对照 LX 与 LX-M

1. 两款软件都完全退出后重新打开，以免上次搜索的内存缓存影响对照；无需删除设置或歌单。
2. 在两边的控制台分别执行同一个诊断脚本，然后选择 QQ 音乐，搜索完全相同的关键词。
3. 首次搜索完成后，分别导出为 `lx-qq-search.json` 和 `lxm-qq-search.json`。先保留这份记录，再测试手动重试。
4. 一并记录两边界面是否显示歌曲、是否需要重试，以及软件代理和系统代理的状态。

比较每次请求的 `time`、`elapsedMs`、`reqCode` 和 `songCount`，不要仅比较控制台有没有红色报错。LX 也可能先收到 `2001`，在内部重试成功后正常显示歌曲。若已有歌曲但 `records` 为空，需要确认是否命中缓存、是否选中 QQ 音乐，以及脚本是否在搜索之前启用。

2026-09-08 的本地对照结果见 [qq-search-comparison.md](./qq-search-comparison.md)。该对照不能替代反馈者机器上的两份日志。
